# 期限日は年月日だけで持ち、時刻は持たない

ADR-0002 の「時刻つきの期限」をやめる。時刻の指定は使わないと判断したため。期限日は年・月・日だけの `CalendarDay` で持つ。`Date` で持たないのは ADR-0002 と同じ理由で、日付は「ある瞬間」ではなく暦の上の1日なので、`Date` で持つとタイムゾーンが変わったときに日付がずれる（東京の 11/25 0:00 は、ニューヨークでは 11/24 になる）。

保存する JSON は、ADR-0002 で決めた `{"date": "2026-11-25"}` の形を保つ。日付だけの期限はすでにこの形で保存されているので、読み替えずにそのまま読める。時刻つきで保存された `{"dateTime": …}` は、読み込んだ Mac のタイムゾーンでのその日の日付として読み、次に保存したときに `{"date": …}` の形になる。

## Considered Options

- 期限日を `"dueDate": "2026-11-25"` のように文字列だけで保存する：見た目は短いが、保存済みの `{"date": …}` も読み続ける必要があり、読む処理が増える。
- 画面からだけ時刻をなくし、モデルの時刻つきの期限は残す：画面では作れないのに、並び順・強調・日付が変わったときの更新の決まりに時刻つきの分岐が残り続ける。
